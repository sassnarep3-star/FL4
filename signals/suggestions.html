SG-07Score strategies on luck-adjusted growth, not on win rateevaluationWin rate and ROI both contain run luck. A skill-based leaderboard needs a metric whose noise is quantified, so a lucky run cannot outrank a better process.Rank on t-statistic of CLV-per-bet and on log-growth after fractional Kelly, both computed on a rolling window; require the sample gate; break ties by how stable the metric is across sub-periods, not by recent hot streaks.HM

SG-08Keep a decision journal that records every failed variantevaluationMultiple testing is the mechanism by which 'no luck' systems still pick winners by luck. Recommended path (the reviewer's job is to accept or edit this order)

Phase 0 - Data existence
Items: SG-01, SG-02, SG-03. Exit criteria: Price snapshots and two or more dated availability snapshots for the same week exist in the repo, each row source-linked.
Phase 1 - Measurement before modelling
Items: SG-04, SG-06, SG-08, SG-13, SG-15. Exit criteria: CLV and availability-accuracy reportable for real events; failed variants logged.
Phase 2 - Models and gates as code
Items: SG-05, SG-09, SG-10, SG-12, SG-18. Exit criteria: gates.py runs in CI; every strategy has a pass/fail record with a config hash.
Phase 3 - Portfolio and pricing
Items: SG-11, SG-16. Exit criteria: Parlays priced on measured correlation only; exposure caps enforced.
Phase 4 - Capital, if and only if gates pass
Items: SG-20, Q-RISK-01, Q-LEGAL-01. Exit criteria: Reviewer-approved budget, legal confirmation, one strategy at a time, kill switch armed.
